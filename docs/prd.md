# PRD

## 目标

构建一个可部署到 Streamlit Cloud 的 POC，验证 AI 能否从企业微信风格聊天存档中判断是否应该介入，并生成可解释的介入建议。

## 用户

主要用户是业务/产品方，需要通过样本复盘理解 agent 的判断依据和稳定性。

## 功能需求

- 上传或选择聊天 JSONL 样本。
- 选择分析到某个 `chatseq` 为止的会话状态。
- 输出结构化决策：是否发送、动作类型、置信度、证据、理由、话术、表单。
- 展示 rubric 评分，帮助业务方判断稳定性。
- 支持多主题样本，用于扩展性验证。
- 支持 LLM 受控增强：让话术更自然、辅助理解复杂聊天语义、生成更易读的业务复盘解释。
- 支持 LLM 增强复盘报告：用固定快照和人工 rubric 验证真实 DeepSeek 输出，避免常规回归受模型波动影响。

## LLM 增强目标

- 话术自然化：在规则已确定动作和表单后，由 LLM 润色候选话术，使其更像业务助理在群聊中自然表达。
- 复杂语义理解：辅助识别项目机会、信息缺口、资料意愿和时间窗口，帮助业务方理解规则未覆盖的表达。
- 复盘解释增强：把证据消息、规则判断和业务语境合成为更易读的解释，方便 PM 和业务负责人复盘。
- 快照化评估：真实 DeepSeek 输出可沉淀为固定快照，后续默认离线复盘话术、语义信号和解释质量。

## 非目标

- 不对接企业微信 API。
- 不构建真实表单系统。
- 不处理会话存档同步频率。
- 不在第一版引入 LangChain/LangGraph。
- LLM 不直接生成真实表单 URL，不绕过 `data/forms.json`，不单独决定是否发送。

## 验收标准

- 泰国港口照明样本在 `chatseq=4` 建议信息收集话术。
- 泰国港口照明样本在 `chatseq=6` 建议发送照明方案收集表单。
- bot、内部员工或普通寒暄后的最新消息不触发发送。
- 所有决策都能给出可复盘的证据和评分。
- DeepSeek 模式可用；无 key、失败或超时时自动回退 Mock/规则结果。
- LLM 输出必须可解释，且不能导致 Stage 2 批量评估回退。
- LLM 增强报告达到默认通过线：语义信号、解释覆盖、话术关键词/克制性均不低于 80%。
